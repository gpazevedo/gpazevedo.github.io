Buyer Team

An autonomous multi-agent negotiation system that takes a purchase requisition from a tenant ERP and returns an issued purchase order. A deterministic Step Functions DAG owns the workflow shape and records every transition; six LLM agents supply judgment at fixed nodes, under runtime guardrails they cannot be prompted past — all inside a ten-cent-per-negotiation cost ceiling.

The problem

Most procurement spend is never negotiated. Not because nobody wants to, but because a buyer's time costs more than the saving on any individual line. Strategic categories get a human and a quarterly review; the long tail gets a catalogue price and a rubber stamp. The economics are the constraint, and they have been for decades.

An agent that can hold a supplier conversation changes that arithmetic — but only if it can be trusted to run without supervision, and only if running it costs essentially nothing. Both conditions are architectural, not model choices. Buyer Team is a reference implementation built to hold both at once: an autonomous negotiation system that takes a purchase requisition from a tenant ERP and returns an issued purchase order, under governance strict enough that a procurement organisation would actually let it run.

Orchestration before intelligence

Everything descends from one decision. A governed, audited business process cannot be run by a model that decides its own next steps. So the system is a hybrid two-level topology: a deterministic Step Functions DAG owns the workflow shape and records every transition, and LLM agents supply judgment at fixed nodes. The orchestrator invokes intelligence; intelligence never invokes the orchestrator.

The workflow is a fixed seven-node graph with exactly one conditional branch — the Kraljic quadrant router at Node 3, which sends a requisition to one of four negotiation strategies — and exactly one governed loop: a single cycle-back from human review, after which the negotiation escalates rather than looping again.

The rigidity is deliberate and its cost is accepted openly. A new negotiation style requires a DAG change rather than a prompt change. In exchange, a misbehaving agent can never alter the workflow shape, which is what makes 100% governance-compliance and audit-completeness targets reachable at all.

The same philosophy governs state. The orchestrator's DynamoDB record is the long-lived truth; agent sessions are ephemeral execution windows. Agents never talk to each other — they communicate only through the orchestrator's shared state — and they hold no cross-session state of their own.

Control lives outside the prompt

Six agents, each owning exactly one cognitive domain, each running as its own isolated runtime. Three principles bound what any of them can do:

  • Tools as boundaries. Every external action is a tool call. The system prompt carries reasoning instructions only; data in and side effects out flow exclusively through typed, idempotent tools.
  • Steering over prompting. Behavioural guardrails are runtime hooks that intercept tool calls outside the reasoning loop. The model cannot forget them, be talked out of them, or be injected past them. Hook failures are fail-closed: a crashed guard suppresses the tool rather than letting it run unchecked.
  • Governance in code, not prompts. Spend gates, budget ceilings, approved-supplier filters, ESG rules, the walk-away price — every policy is enforced by deterministic code at a specific node.

That third principle has a number attached, and it is the one worth carrying into any conversation about agent safety: instructing a model to respect a constraint achieved 82.5% compliance. Enforcing the same constraint at the runtime boundary achieves 100%, because it is no longer a thing the model can be persuaded about. The approval gate at Node 6 is the clearest case — a pure function over policy and state, with no model involved in the decision to require human review. It cannot be reasoned around, retried out of, or convinced to skip itself for an unusual edge case.

Where a model earned its place, and where it didn't

The recurring test is does this step need judgment, or just correctness? Only judgment earns a model invocation, and the test was applied ruthlessly enough to reverse work already built.

Bid evaluation was originally an LLM agent. It became inline Python scoring, because multi-dimensional comparison against fixed weights is arithmetic, not judgment — and arithmetic done by a model is arithmetic you have to evaluate, monitor, and pay for. Low-value spot bids skip the agent entirely. Rejection letters are template renders. Structured responses are assembled in code from the tool-call transcript rather than by a second model call.

Removing an agent that already worked is a harder decision than not building one. It is also the one that most improved the system.

Surviving the wait

A negotiation is not a request. It spans supplier response times, and it stops dead at the human approval gate for as long as the approver takes. Holding a live execution open across that window is not an option, so the graph serialises its state and tears execution down — for up to 96 hours the negotiation is simply a row in DynamoDB.

Underneath, every node writes a versioned checkpoint on completion, and node contracts are idempotent, so a crash mid-auction resumes from the last completed node rather than restarting the negotiation. Durable execution is what lets the workflow be honest about time.

The cost ceiling

The load-bearing business number is under ten cents per negotiation. Above that, the economics that made the tail unnegotiable in the first place reassert themselves and the whole premise collapses.

Four shipped mechanisms hold it: a three-tier Amazon Nova model ladder that puts the cheap tier on classification, spot bidding and award communications while reserving the capable tier for the three strategy-execution nodes; partial prompt caching; a Kraljic classifier cached for 24 hours, so it mostly never runs; and a context-compaction hook. Each is a real trade-off — how much of the request to cache versus keep fresh, how much classification to skip versus recompute, how much context to keep versus discard — rather than a switch someone flipped.

An earlier version of this cost story was larger and partly aspirational: a second model family, nightly batch inference, an hourly CUR/Athena pipeline attributing the AWS bill to per-tenant token counts. A repo audit established that none of the three had been built. They are deferred deliberately rather than described as present — building an attribution layer on top of a cost number nobody had verified would have turned an honest absence into a confidently wrong chargeback figure.

What it is not

Buyer Team is deployed to a production engineering standard. It has no live tenants, and "production-grade" here is a claim about the engineering, not about operating a live SaaS. Bids are self-seeded — there is no real supplier inbound path — so the negotiation logic is exercised against synthetic counterparties rather than commercial ones.

Both are constraints rather than oversights, and stating them plainly is the point: an architecture is only worth reading if you know which parts of it have met reality. The production promotion gate has been blocked for five consecutive weeks on a synthetic human-label data gap — the evaluation harness cannot yet be calibrated against real human judgment, so the gate stays shut. That is the system working as designed, and it is also the most useful thing about it to discuss.
