PR to PO: one spine,
four negotiation strategies

Every negotiation this system runs takes the same path from purchase requisition to purchase order — the same six node Lambdas, in the same order, with the same checkpoints. The four Kraljic strategies differ in exactly one place. This walks that path one stage at a time, and you can pick which strategy runs.

What you are looking at

The top row is the shared head: ingestion through the gateway, validation and admission control, Kraljic classification, and a Choice state that reads the resulting quadrant. The bottom row is the shared tail: deterministic bid evaluation, the approval gate, award, and PO delivery. Between them sits Node 3 — one Lambda with four dispatch targets, and the only place the strategies diverge at all.

Two of the four branches carry a deterministic bypass: below a configurable floor, the strategy agent is never invoked and pricing runs inline in the node Lambda. Toggle the value between ≤ $5k and > $5k on those branches to see the difference — and watch the cost readout, which only moves when an agent is actually called.

Two failures are staged deliberately, because they are the parts worth seeing rather than reading about. The LEVERAGE run loses its runtime in the middle of round 3 and resumes from the last checkpoint without re-sending a single invitation. The BOTTLENECK run loses a tool and degrades to an approximated calculation rather than failing the round.

The costs on the badges

Those are measured across 23 end-to-end negotiations, not estimated. The two above-threshold runs are marked modelled in the readout, because every spot and auction negotiation in that dataset happened to fall under the bypass — the agent path for those two quadrants is real code that the measured sample simply never exercised.
